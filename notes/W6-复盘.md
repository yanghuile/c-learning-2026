# W6 复盘（2026.10.12 – 10.18）

> 主题：环形缓冲区（嵌入式最核心的数据结构）

1.环形缓冲的两种满/空判定方案分别是什么？各自代价是什么？
答：方案A是牺牲一格不放数据；方案B是增加一个计数器。代价：方案A实际容量=总容量-1，有一个内存被浪费，并且容量只有1时，方案A永远不能存储数据；方案B的结构体多占 4 字节内存（多一个 uint32_t count 成员）， 但可用存储容量比方案 A 多 1 个元素。

2.为什么不能只靠 read == write 判断空或满？
答：当缓冲区为空时，read==write；当缓冲区写满时，write回绕到起始位置，此时read==write。因此read==write会有歧义，不能判断是空还是写满。

3.方案 A 在 capacity == 1 时为什么完全不能工作？
答：方案A是预留一个空位的环形缓冲，可用容量为总容量减1。当capacity==1时，需要把仅有的这1个单元留做空位，没有剩余空间存放有效数据，缓冲区存不了任何内容，因此无法工作。

4.批量接口（rb_write/rb_read）为什么要返回"实际处理数"，而不是 0/1？
答：如果返回0/1，调用方只知道整体写入/读取成功或失败。如果只是成功写入/读取一部分，调用方不知道哪些数据是已经被写入/读取，哪些数据还没有处理。而返回“实际处理数”就能让调用方清楚知道这一轮写入/读取多少数据，还没有写入/读取的数据下一轮可以接着处理。

5.a_count 为什么必须写 (write - read + CAP) % CAP？如果写成 (write - read) % CAP，什么时候会出错？算出来的值是多少？
答：如果写成 (write - read) % CAP，当write<read时，write - read得到负数，逻辑出错，会越界。
(write - read) % CAP       = (2 - 6) % 8  = (-4) % 8  = -4      ❌
(write - read + CAP) % CAP = (2 - 6 + 8) % 8 = 4 % 8  = 4       ✅

关键：C 语言里 -4 % 8 = -4
      因为 C99 规定整数除法向零截断，余数和被除数同号。

a_count 返回 int 时是 -4；如果这个值被赋给 uint32_t：
uint32_t n = a_count(&rb);    /* -4 → 0xFFFFFFFC = 4294967292 */
for (i = 0; i < n; i++) ...   /* 循环 42 亿次 → 卡死/越界崩溃 */
