## 四、电路（超简单）

```
ESP32                   外部电路
┌──────────┐
│ GPIO15 ──┼───[220Ω]───┬──► LED 阳极（长脚）
│          │            │
│   GND  ──┼────────────┴──► LED 阴极（短脚）
└──────────┘
```

**电流计算**（必答思考题第 4 题）：
```
Vcc = 3.3V（GPIO 高电平）
Vf  = 2.0V（红色 LED 正向压降）
R   = 220Ω
I = (3.3 - 2.0) / 220 ≈ 5.9 mA
```
**5.9 mA < 28 mA（GPIO 最大灌电流）→ 安全** ✅

**自检清单（上电前）**：
- [ ] LED 长脚朝电阻方向（阳极），短脚朝 GND（阴极），没接反
- [ ] 电阻 220Ω 已确认
- [ ] 杜邦线都插紧，无虚接
- [ ] GPIO15 和 GND 接的是标注引脚

## 七、必答思考题（报告里必须作答，占 10 分）

| # | 题目 | 准备要点 |
|---|---|---|
| **1** | 简述 WiFi 家电远程控制的**完整通信链路**并画示意框图。**为什么设备要主动连接云端，而不是等手机直接连设备？** | 手机 → 公网 → Broker → ESP32；主动连的原因：手机 IP 不固定、设备在 NAT 后面、省电、可多客户端 |
| **2** | 解释 MQTT 的**发布-订阅**模型，对比 HTTP **请求-响应**的区别。**为什么物联网控制更适合 MQTT？** | 解耦、一对多、长连接、开销小、支持 QoS；HTTP 需要设备做服务器、轮询浪费 |
| **3** | **家庭断网后，WiFi 智能家电还能远程控制吗？本地控制还能用吗？** | 远程不能（云端链路断）；本地要分情况（纯云设备不行，有本地协议的可以） |
| **4** | 计算 LED 电路工作电流，判断是否在 GPIO 安全范围 | `(3.3-2.0)/220 ≈ 5.9mA` < 28mA → 安全 |
| **5** | **为什么智能家电多用 2.4GHz 而不是 5GHz？** | 穿透力、覆盖范围、成本、功耗；5G 速率高但穿墙差、功耗高 |

## 八、常见坑（文档第八章，做实验时对照）

### WiFi 问题

| 现象 | 原因 |
|---|---|
| 一直输出 `...` 最后失败 | 密码错（注意大小写） |
| 搜不到 WiFi | **ESP32 只支持 2.4GHz**，5G 不行 |
| 时断时续 | 信号弱 |
| 手机和 ESP32 同 WiFi 但 ping 不通 | 路由器开了 **AP 隔离** |

### MQTT 问题

| 现象 | 原因 |
|---|---|
| 错误码 **-2** | 网络不通 / DNS 失败 |
| 连上几分钟就断 | 心跳超时 —— **`client.loop()` 要高频调用**，别在 loop 里长 delay |
| 发布收不到 | **Topic 名不匹配**（区分大小写） |
| 偶尔丢消息 | QoS=0，改成 **QoS=1** |

### 硬件问题

| 现象 | 原因 |
|---|---|
| LED 不亮 | **正负极接反** |
| LED 很暗 | 电阻太大 / 电压不够 |
| **上传失败 "Timed out waiting for packet header"** | 未进下载模式 → **按住 BOOT 再点上传** |
| ESP32 反复重启 | **GPIO15 外部拉高影响启动**（GPIO15 是 strapping pin） |

### 软件问题

| 现象 | 原因 |
|---|---|
| 编译找不到 `WiFi.h` | 开发板选成了普通 Arduino → 选 **ESP32 Dev Module** |
| 找不到 `PubSubClient.h` | 库没装 |
| 串口乱码 | 波特率不匹配 → 设 **115200** |

## 九、这个任务对求职的价值（我的判断）

| 价值 | 说明 |
|---|---|
| ⭐⭐ **补上计划里没有的通信协议** | 原计划只有 CAN/Modbus/EtherCAT，**没有 WiFi/TCP-IP/HTTP/MQTT** |
| ⭐⭐ **MQTT 是物联网岗位高频关键词** | 智能家居、工业物联网方向的 JD 常提 |
| ⭐ **能形成"通信协议对比"的面试谈资** | 你可以讲：**CAN**（多主、仲裁、实时）vs **Modbus**（主从、简单）vs **WiFi/MQTT**（云端、一对多、弱实时）—— **这是很加分的回答** |
| ⭐ **和 DHT11 拓展呼应** | 江协套件里有 DHT11，可以直接复用到"拓展二：温湿度上报" |

**但要注意**：它是**演示性质**的任务（不是从零设计），**所以对简历的分量不如电子作品设计**。
