## G4 详解：有符号 vs 无符号的右移（**嵌入式高频陷阱**）

```c
unsigned int u = 0xFFFFFFF8u;
printf("%X\n", u >> 1);        /* 0x7FFFFFFC —— 最高位补 0 */
```

| 类型 | 右移时最高位补 | 名称 |
|---|---|---|
| **有符号** `int`（负数） | 补 **1**（保持符号） | 算术右移 |
| **无符号** `unsigned` | 补 **0** | 逻辑右移 |

```
原值        : 1111 1111 1111 1111 1111 1111 1111 1000
unsigned >> : 0111 1111 1111 1111 1111 1111 1111 1100 → 0x7FFFFFFC = 2147483644
signed   >> : 1111 1111 1111 1111 1111 1111 1111 1100 → 0xFFFFFFFC = -4
```

**同一个二进制数，一个变成 21 亿，一个变成 -4。**

**教训**：嵌入式里处理数据（ADC 值、寄存器内容、协议字段）**一律用 `unsigned`**，
因为无符号的位运算行为可预测，不会因为"符号位"产生意外结果。

**为什么容易错**：你答对了 G3（有符号），说明懂有符号的规则；
但没注意到 G4 加了 `u` 后缀，类型变成无符号，规则就变了。
**看题要先看类型** —— 这是这次的核心教训。

## G8 详解：`return value |= (1<<n);` 的问题

功能正确（C 规定赋值表达式的值就是被赋的值），但：

```c
return value |= (1<<n);     /* ⚠️ 改了 value 这个局部变量，再返回它 */
return value |  (1<<n);     /* ✅ 直接算结果返回，一眼看懂 */
```

**为什么不好**：如果有人后续在同一个函数里继续用 `value`，用到的已经是**改过的值**：

```c
unsigned char f(unsigned char value, int n)
{
    value |= (1 << n);
    return value | 0x01;    /* 这里用的已经是改过的 value！容易看漏 */
}
```

**这是"能跑但不清晰"的典型** —— 编译器不会报错，测试也能过，但维护的人要绕一下才看懂。
